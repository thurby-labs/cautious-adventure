# Contributing

## Development model

Use trunk-based development.

- Keep changes small where possible.
- Use branches for changes that need isolation.
- Open pull requests for substantial changes.
- Directly commit only routine, low-risk maintenance when appropriate.

## Conventional commits

Use formats such as:

- `feat:` new capability or content area
- `fix:` correction
- `docs:` documentation-only change
- `research:` research or source updates
- `refactor:` structural improvement without behavior change
- `test:` tests or validation
- `chore:` maintenance

Example:

`research: add official AEP identity documentation`

## Pull request expectations

Substantial pull requests should explain:
- what changed
- why it changed
- sources or evidence used
- risks and assumptions
- validation performed

Automated checks should pass before merge.
