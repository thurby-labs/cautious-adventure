# Repository Guide

## Main areas

| Area | Purpose |
|---|---|
| `_shared/ai-tools/` | Tool selection and current tool profiles |
| `_shared/instructions/` | Cross-cutting research, writing, and coding guidance |
| `_shared/prompts/` | Reusable copy/paste prompts |
| `_shared/skills/` | Reusable methods with inputs, process, outputs, and checks |
| `_shared/recipes/` | End-to-end workflows combining multiple skills/tools |
| `_shared/evaluation/` | AI output and POC evaluation |
| `_shared/security/` | Public-repository and AI data safeguards |
| `_shared/roles/` | Reusable perspectives for analysis |
| `_shared/templates/` | Durable artifact templates |
| `personal/` | Public-safe personal POCs, notes, samples, productivity |
| `adobe/` | Public-safe Adobe knowledge, consulting, projects, prompts, templates |
| `docs/` | Repository documentation, command center, source index, learning |
| `tools/` | Automation and script documentation |

## Placement rule

If something answers **which tool**, use `ai-tools`.

If it answers **how to perform a repeatable method**, use `skills`.

If it is a **copy/paste instruction**, use `prompts`.

If it combines several steps or tools into an **end-to-end workflow**, use `recipes`.

If it evaluates output or a POC, use `evaluation`.

If it protects data or the public repository, use `security`.

Avoid creating a new category when an existing one fits.
