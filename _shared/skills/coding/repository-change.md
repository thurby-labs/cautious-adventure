# Repository Change Skill

## Purpose

Make a controlled change to an existing repository.

## Method

1. Read root and path-specific instructions.
2. Inspect the relevant files and tests.
3. State the intended change before editing.
4. Make the smallest coherent change.
5. Run applicable validation.
6. Inspect the diff.
7. Check for secrets, PII, generated noise, and unrelated edits.
8. Update documentation if behavior changed.
9. Record decisions or handoff state when the work is substantial.

## Completion criteria

A repository change is not complete merely because the code runs. It is complete when implementation, validation, documentation, and handoff state are consistent.
